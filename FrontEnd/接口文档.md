# DZ_DianPing_Front 项目接口文档

> 本文档依据当前项目源码整理，覆盖 `com.dzdp.controller` 下全部有效接口。
>
> - 项目：DZ_DianPing_Front
> - 后端端口：`8080`
> - 基础地址：`http://localhost:8080`
> - API 前缀：当前 Controller 没有统一 `/api` 前缀
> - 有效接口数量：31 个
> - 数据格式：未特别说明时，请求体和响应体均为 `application/json`

如果后续通过 Nginx 统一代理，约定前端请求 `/api/user/login`，由 Nginx 去除 `/api` 后转发到后端 `/user/login`。

---

## 1. 通用约定

### 1.1 鉴权方式

除标记为“公开”的接口外，其余接口需要在请求头中携带登录令牌：

```http
authorization: <登录接口返回的原始 Token>
```

注意：当前后端直接读取 `authorization` 的值，不会再去除 `Bearer ` 前缀。因此请求头应直接填写 Token，不能写成 `Bearer <Token>`。

登录 Token 在 Redis 中的初始有效期为 30 分钟；携带有效 Token 访问接口时会刷新有效期。

未登录或 Token 无效时，受保护接口返回 HTTP `401`，当前响应体为空。

### 1.2 统一响应结构

Controller 返回 `Result`，字段如下：

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | Boolean | 业务是否成功 |
| `errorMsg` | String | 业务失败信息 |
| `data` | Object | 业务数据，类型由具体接口决定 |
| `total` | Long | 总记录数；当前大多数列表接口没有返回该字段 |

项目开启了 `spring.jackson.default-property-inclusion: non_null`，值为 `null` 的字段不会出现在 JSON 中。

成功响应示例：

```json
{
  "success": true,
  "data": {}
}
```

业务失败响应示例：

```json
{
  "success": false,
  "errorMsg": "业务错误信息"
}
```

无数据的成功响应通常为：

```json
{
  "success": true
}
```

### 1.3 HTTP 状态与异常

| 状态码 | 场景 | 响应说明 |
|---|---|---|
| `200` | 请求处理完成 | 可能是成功，也可能是 `success=false` 的业务失败 |
| `401` | 未登录或 Token 无效 | 当前无响应体 |
| `404` | 路径或静态资源不存在 | 由 Spring Boot 或 Nginx 返回 |
| `429` | 触发接口限流 | `Result`，并带 `Retry-After` 响应头，单位为秒 |
| `500` | 服务器未处理异常 | 当前 `RuntimeException` 可能被异常处理器转换为 HTTP 200 + `success=false` |

前端不能只根据 HTTP `200` 判断业务成功，还应检查 `response.data.success`。

限流响应示例：

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 2
Content-Type: application/json

{
  "success": false,
  "errorMsg": "操作过于频繁，请稍后再试"
}
```

### 1.4 时间与金额

- `LocalDateTime`、`LocalDate` 由 Jackson 序列化为日期时间字符串或日期字符串。
- 时间字段具体格式以运行环境 Jackson 配置为准。
- `Voucher.payValue`、`Voucher.actualValue` 为 `Long`，文档不擅自换算单位；前端应沿用数据库约定。

### 1.5 分页约定

页码参数 `current` 从 `1` 开始。

- 默认页大小：`5`
- 当前最大页大小：`10`
- 最大页码：`100`
- 小于 `1` 的页码会被修正为 `1`
- 大于 `100` 的页码会被截断为 `100`
- 大多数列表接口只返回 `data` 数组，不返回真实总记录数

`/blog/of/follow` 使用滚动分页，不使用普通页码分页，返回 `ScrollResult`。

## 3. 用户接口

### 3.1 发送登录验证码

- 请求方式：`POST`
- 请求路径：`/user/code`
- 鉴权：公开
- Content-Type：无请求体，参数位于 Query String

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| `phone` | Query | String | 是 | 无 | 手机号 |

请求示例：

```http
POST /user/code?phone=13800138000
```

成功响应：

```json
{
  "success": true,
  "data": "短信验证码已发送"
}
```

可能失败：

```json
{
  "success": false,
  "errorMsg": "手机号格式错误"
}
```

限流规则：

- 同一手机号约每 60 秒一次。
- 同一 IP 约每 60 秒最多 10 次。
- 触发限流返回 HTTP `429`。

当前项目在开发环境将验证码输出到后端日志，未真正接入短信平台。

### 3.2 登录

- 请求方式：`POST`
- 请求路径：`/user/login`
- 鉴权：公开
- Content-Type：`application/json`

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `phone` | Body | String | 是 | 手机号 |
| `code` | Body | String | 是 | 验证码；当前登录流程只校验验证码 |
| `password` | Body | String | 否 | 当前登录实现未读取该字段 |

请求体示例：

```json
{
  "phone": "13800138000",
  "code": "123456",
  "password": ""
}
```

成功响应：

```json
{
  "success": true,
  "data": "a1b2c3d4e5f6"
}
```

`data` 是后续请求使用的原始登录 Token。

可能失败：

| `errorMsg` | 说明 |
|---|---|
| `手机号格式错误` | 手机号格式不合法 |
| `验证码不一致，请重新输入` | 验证码错误或已过期 |

限流：同一手机号约每 60 秒最多 5 次，同一 IP 约每 60 秒最多 60 次。

### 3.3 退出登录

- 请求方式：`POST`
- 请求路径：`/user/logout`
- 鉴权：需要登录
- 请求参数：无

当前实现只清理当前请求线程中的用户上下文，没有删除 Redis Token，并固定返回：

```json
{
  "success": false,
  "errorMsg": "功能未完成"
}
```

因此该接口目前不能作为完整的退出登录能力使用。

### 3.4 获取当前登录用户

- 请求方式：`GET`
- 请求路径：`/user/me`
- 鉴权：需要登录
- 请求参数：无

成功响应：

```json
{
  "success": true,
  "data": {
    "id": 1,
    "nickName": "user_xxxx",
    "icon": ""
  }
}
```

成功时 `data` 类型为 UserDTO。

### 3.5 获取用户详情资料

- 请求方式：`GET`
- 请求路径：`/user/info/{id}`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 用户 ID |

成功响应 `data` 为 UserInfo；如果未找到资料，则返回无 `data` 的成功响应。

接口会主动清除响应中的 `createTime` 和 `updateTime`。

### 3.6 查询用户简要信息

- 请求方式：`GET`
- 请求路径：`/user/{id}`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 用户 ID |

成功响应 `data` 为 UserDTO；用户不存在时返回无 `data` 的成功响应。

### 3.7 用户签到

- 请求方式：`POST`
- 请求路径：`/user/sign`
- 鉴权：需要登录
- 请求参数：无

成功响应：

```json
{
  "success": true
}
```

重复签到不会报错，Redis BitMap 对应位保持为已签到。

### 3.8 查询本月连续签到天数

- 请求方式：`GET`
- 请求路径：`/user/sign/count`
- 鉴权：需要登录
- 请求参数：无

成功响应：

```json
{
  "success": true,
  "data": 3
}
```

`data` 类型为 Integer，表示截至当天的本月连续签到天数。

## 4. 店铺接口

### 4.1 根据 ID 查询店铺

- 请求方式：`GET`
- 请求路径：`/shop/{id}`
- 鉴权：公开

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 店铺 ID |

成功响应 `data` 类型为 Shop。

店铺不存在：

```json
{
  "success": false,
  "errorMsg": "店铺不存在！"
}
```

该接口使用 Redis 逻辑过期缓存。

### 4.2 新增店铺

- 请求方式：`POST`
- 请求路径：`/shop`
- 鉴权：当前为公开
- Content-Type：`application/json`

请求体为 Shop 对象，字段见“Shop 对象”。

成功响应：

```json
{
  "success": true,
  "data": 1001
}
```

`data` 为新增后的店铺 ID。

注意：虽然该接口是写操作，但当前 `/shop/**` 整个前缀都被登录拦截器排除，所以不会强制登录。

### 4.3 修改店铺

- 请求方式：`PUT`
- 请求路径：`/shop`
- 鉴权：当前为公开
- Content-Type：`application/json`

请求体为 Shop 对象，必须提供要更新的 `id`。

成功响应：

```json
{
  "success": true
}
```

未提供 ID 时：

```json
{
  "success": false,
  "errorMsg": "店铺id不能为空"
}
```

### 4.4 按类型分页查询店铺

- 请求方式：`GET`
- 请求路径：`/shop/of/type`
- 鉴权：公开

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| `typeId` | Query | Integer | 是 | 无 | 店铺分类 ID |
| `current` | Query | Integer | 否 | `1` | 页码 |
| `x` | Query | Double | 否 | 无 | 当前经度 |
| `y` | Query | Double | 否 | 无 | 当前纬度 |

返回规则：

- 未传 `x` 或 `y`：按 ID 升序从数据库分页，每页 5 条。
- 同时传 `x` 和 `y`：查询该坐标 5 公里内的店铺，按距离排序，每页 5 条，并为每条 Shop 填充 `distance`。

成功响应：

```json
{
  "success": true,
  "data": []
}
```

`data` 类型为 List\<Shop>。

### 4.5 按名称分页查询店铺

- 请求方式：`GET`
- 请求路径：`/shop/of/name`
- 鉴权：公开

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| `name` | Query | String | 否 | 无 | 店铺名称前缀 |
| `current` | Query | Integer | 否 | `1` | 页码 |

当前使用名称前缀匹配，即 `name LIKE '关键字%'`，不是任意位置包含。

成功响应 `data` 类型为 List\<Shop>，每页最多 10 条，按店铺 ID 倒序。

### 4.6 查询店铺分类列表

- 请求方式：`GET`
- 请求路径：`/shop-type/list`
- 鉴权：公开
- 请求参数：无

成功响应 `data` 类型为 List\<ShopType>，按 `sort` 升序。

无分类数据时：

```json
{
  "success": false,
  "errorMsg": "没有分类数据"
}
```

## 5. 博客接口

### 5.1 发布探店笔记

- 请求方式：`POST`
- 请求路径：`/blog`
- 鉴权：需要登录
- Content-Type：`application/json`

请求体为 Blog 对象，字段见“Blog 对象”。

后端会使用当前登录用户覆盖请求体中的 `userId`，客户端传入的 `userId` 不生效。

成功响应：

```json
{
  "success": true,
  "data": 2001
}
```

`data` 为新增博客 ID。

可能失败：

```json
{
  "success": false,
  "errorMsg": "新增笔记失败"
}
```

### 5.2 点赞或取消点赞

- 请求方式：`PUT`
- 请求路径：`/blog/like/{id}`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 博客 ID |

接口根据当前用户是否已经点赞执行切换操作：

- 未点赞：点赞数加一。
- 已点赞：点赞数减一，并取消点赞。

成功响应：

```json
{
  "success": true
}
```

### 5.3 查询当前用户发布的笔记

- 请求方式：`GET`
- 请求路径：`/blog/of/me`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| `current` | Query | Integer | 否 | `1` | 页码 |

成功响应 `data` 类型为 List\<Blog>。

列表按创建时间、ID 倒序，每页最多 10 条。为减少数据传输，列表不返回 `content`、`updateTime`。

### 5.4 查询热门笔记

- 请求方式：`GET`
- 请求路径：`/blog/hot`
- 鉴权：公开；如果携带有效 Token，会补充当前用户的点赞状态

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| `current` | Query | Integer | 否 | `1` | 页码 |

成功响应 `data` 类型为 List\<Blog>，按点赞数、ID 倒序，每页最多 10 条。

列表不返回 `content`、`updateTime`，但会填充作者 `name`、`icon` 和当前用户的 `isLike`。

### 5.5 查询博客详情

- 请求方式：`GET`
- 请求路径：`/blog/{id}`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 博客 ID |

成功响应 `data` 类型为 Blog，包含正文 `content`，并填充作者与当前用户点赞状态。

博客不存在：

```json
{
  "success": false,
  "errorMsg": "博客不存在"
}
```

### 5.6 查询博客点赞用户

- 请求方式：`GET`
- 请求路径：`/blog/likes/{id}`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 博客 ID |

成功响应 `data` 类型为 List\<UserDTO>，最多返回最近点赞的 5 名用户。

### 5.7 查询指定用户发布的笔记

- 请求方式：`GET`
- 请求路径：`/blog/of/user`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|---|
| `id` | Query | Long | 是 | 无 | 目标用户 ID |
| `current` | Query | Integer | 否 | `1` | 页码 |

成功响应 `data` 类型为 List\<Blog>。

列表按创建时间、ID 倒序，每页最多 10 条，不返回正文 `content` 和 `updateTime`。

### 5.8 查询关注流

- 请求方式：`GET`
- 请求路径：`/blog/of/follow`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `lastId` | Query | Long | 是 | 上一次返回的 `minTime` 时间戳；首次请求按前端约定传入当前时间戳 |
| `offset` | Query | Integer | 否 | 同一时间戳下已经读取的数量，默认 `0` |

成功响应 `data` 类型为 ScrollResult：

```json
{
  "success": true,
  "data": {
    "list": [],
    "minTime": 1760000000000,
    "offset": 1
  }
}
```

分页方式：

1. 首次请求传入当前时间戳作为 `lastId`，`offset` 传 `0`。
2. 保存响应中的 `data.minTime` 和 `data.offset`。
3. 下一页将这两个值分别作为新的 `lastId` 和 `offset`。
4. 如果当前用户没有关注流数据，返回无 `data` 的成功响应。

## 6. 关注接口

### 6.1 关注或取消关注

- 请求方式：`PUT`
- 请求路径：`/follow/{id}/{isFollow}`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 目标用户 ID |
| `isFollow` | Path | Boolean | 是 | `true` 表示关注，`false` 表示取消关注 |

成功响应：

```json
{
  "success": true
}
```

重复关注会按幂等成功处理。

### 6.2 查询是否已关注

- 请求方式：`GET`
- 请求路径：`/follow/or/not/{id}`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 目标用户 ID |

成功响应：

```json
{
  "success": true,
  "data": true
}
```

`data` 类型为 Boolean。

## 8. 秒杀订单接口

### 8.1 秒杀下单

- 请求方式：`POST`
- 请求路径：`/voucher-order/seckill/{id}`
- 鉴权：需要登录

请求参数：

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `id` | Path | Long | 是 | 优惠券 ID |

成功响应：

```json
{
  "success": true,
  "data": 188888888888888888
}
```

`data` 为 Long 类型订单 ID。订单请求先完成 Redis 原子预扣，并将订单消息发送到 RabbitMQ；落库由消费者异步完成。

可能失败：

| `errorMsg` | 说明 |
|---|---|
| `库存不足` | Redis 预扣库存不足 |
| `不能重复下单` | 当前用户已经参与过该券秒杀 |
| `秒杀商品不存在或已下架` | Redis 中未初始化该券库存 |
| `下单失败，请稍后重试` | 订单消息投递失败 |
| `操作过于频繁，请稍后再试` | 同用户限流 |
| `当前网络请求过于频繁，请稍后再试` | 同 IP 限流 |

限流规则：

- 同一登录用户约每 2 秒 1 次。
- 同一 IP 约每秒 30 次，允许一定突发量。
- 限流响应为 HTTP `429`，并带 `Retry-After`。

## 9. 文件接口

### 9.1 上传博客图片

- 请求方式：`POST`

|---|---|---|---|---|


```json

```

文件实际保存目录当前硬编码为：

```text
D:\tlias\nginx-1.18.0 dianping\html\hmdp\imgs
```

即返回的 `/blogs/...` 需要由 Nginx 或后端静态资源映射提供访问。

## 11. 当前鉴权边界说明

当前登录拦截器明确排除了以下路径前缀：

```text
/user/login
/user/code
/upload/**
/voucher/**
/shop/**
/shop-type/**
/blog/hot
```

因此：

- `/shop` 的新增和修改接口目前不需要登录。
- `/voucher` 的新增秒杀券接口目前不需要登录。
- `/upload/**` 的上传和删除接口目前不需要登录。
- `/blog/hot` 是博客模块中唯一直接公开的接口。

这些规则是当前代码的实际行为，不代表推荐的生产安全配置。接入 Vue3 和 Nginx 前，建议将管理写接口改成需要登录，并限制 `/upload/blog/delete` 的访问权限。
